Bounds on edit-metric codes

Eq(n,d) is the largest number of words of length n over q symbols such that every two of them are at Levenshtein distance at least d. The distance counts the insertions, deletions and substitutions needed to turn one word into the other. These tables give the best known bounds for binary, ternary and quaternary codes of fixed length, and for binary and ternary codes of variable length.

The tables start from Sheridan Houghten's tables at Brock University, copied on 27 October 2026, and record improvements found since then. 62 cells have a better lower bound than Houghten's table, and 12 more follow from those. One more follows from other entries of Houghten's own tables. Every new lower bound that comes with a code links to the codewords and their SHA-256, and check.py checks any of them. This page is maintained separately from Houghten's.

Last updated 2026-11-06. Corrections and new codes are welcome at ayeung16@stanford.edu. Data: bounds.csv (every cell, with its source), records.csv (every claim beyond Houghten's table).

Notes

Reading the tables

A single number is the exact value. a–b means the value is between a and b. ≥a means only a lower bound is known. Hover a coloured cell to see where its value comes from and what Houghten's table gives; click it to jump to its entry in the list of improvements. In the variable-length tables a code may contain words of any length up to n, the empty word included.

Bounds that follow from others

Appending the same symbol to every word of a code leaves all distances unchanged, so Eq(n+1,d) ≥ Eq(n,d). A code with minimum distance d+1 also has minimum distance d, so Eq(n,d) ≥ Eq(n,d+1). Cells marked as following from an improved cell take their value this way. Every upper bound is Houghten's.

Checking a code

Each code file has a short header declaring q, n, d, the size and the SHA-256 of the sorted codewords, followed by one word per line. check.py needs only Python 3 and checks one file at a time:

python3 check.py codes/edit4_n13_d3_size500882.txt

Before it was listed, each code here was also accepted by three verifiers that share no code: a ball-marking check, a sort-based ball-collision check and a pairwise bit-parallel Levenshtein check.

How the new codes were found

The entries from Yeung 2026 came from searching for codes invariant under a chosen group of symbol permutations and reversal, which shrinks the search to orbits of words. Of the entries first published here, the large quaternary ones are lexicodes: take the words in lexicographic order and keep each one that is far enough from every word kept so far. The binary and ternary ones come from iterated local search for a maximum independent set in the conflict graph, whose vertices are all qn words, with an edge between two words closer than d. Where that graph is too large, the search runs on the graph of orbits under a small group of symbol permutations and reversal, which the paper uses for the quaternary cells. The same search reproduces every exact value it was run on before any open cell was believed. All of these searches were run by an LLM coding agent under the protocol in the paper, which also describes what went wrong along the way.
